# Obsidian 高级 Markdown 语法指南

本文档是 Obsidian 方言 Markdown（Obsidian Flavored Markdown）的**权威速查**。这些语法大多依赖 Obsidian 渲染，不属于标准 CommonMark——在笔记中使用前对照本文档，需要发布到 GitHub 等平台时注意第 6 节的兼容性说明。

## 0. 语法总览

| 语法 | 写法 | 用途 |
|------|------|------|
| Callout 提示块 | `> [!tip]` | 带图标与配色的提示/警告/示例块 |
| 行内脚注 | `文字^[脚注内容]` | 就地写脚注，自动排入文末 |
| 标准脚注 | `文字[^id]` + `[^id]: 内容` | 定义与引用分离的脚注 |
| 双链 | `[[笔记]]` | 笔记间互链，反向链接基石 |
| 嵌入 | `![[笔记/图片]]` | 把另一篇笔记/图片/PDF 内联进当前笔记 |
| 高亮 | `==文字==` | 黄底高亮（也是闪卡挖空语法基础） |
| 注释 | `%% 内容 %%` | 阅读视图不可见的批注 |
| 块引用 ID | 段落末 ` ^block-id` | 让段落可被 `[[#^id]]` 精确引用 |

## 1. Callout 提示块

### 1.1 基本写法

```markdown
> [!tip] 小技巧
> 这里是要强调的内容。
> 可以写多行，每行都要以 `>` 开头。
```

- 首行必须是 `> [!类型]`；类型**大小写不敏感**（`[!TIP]` 与 `[!tip]` 等价）。
- **空行也必须是 `>`**（即 `>` 后什么都不写），否则 Callout 提前结束、后半段变成普通引用。

### 1.2 全部类型与别名

| 类型 | 别名 | 默认颜色 | 典型用途 |
|------|------|---------|---------|
| `note` | — | 蓝 | 普通备注 |
| `abstract` | `summary`、`tldr` | 青 | 摘要 |
| `info` | — | 蓝 | 信息 |
| `todo` | — | 蓝 | 待办 |
| `tip` | `hint`、`important` | 绿 | 技巧/重点 |
| `success` | `check`、`done` | 绿 | 完成/正确 |
| `question` | `help`、`faq` | 黄 | 疑问 |
| `warning` | `caution`、`attention` | 黄 | 警告 |
| `failure` | `fail`、`missing` | 红 | 失败 |
| `danger` | `error` | 红 | 危险/错误 |
| `bug` | — | 红 | Bug |
| `example` | — | 紫 | 示例 |
| `quote` | `cite` | 灰 | 引文 |

- 别名之间完全等价（如 `[!important]` 渲染效果 = `[!tip]`）；选择**语义最贴合**的类型，不要只看颜色。
- 类型写错（如 `[!tips]`）→ 退化为普通引用块，无任何图标配色。

### 1.3 自定义标题与折叠

```markdown
> [!warning] 这个坑很多人踩过
> 标题文字直接跟在类型后。

> [!faq]- 默认折叠的 Callout
> 类型后加 `-`，阅读时默认收起。

> [!faq]+ 默认展开的 Callout
> 类型后加 `+`，阅读时默认展开（同不写符号，但显示折叠箭头）。
```

### 1.4 嵌套

```markdown
> [!note] 外层
> 外层内容。
> > [!example] 内层
> > 用 `>>` 嵌套第二层。
```

## 2. 脚注（行内 `^[...]` 与标准 `[^id]`）

### 2.1 行内脚注

```markdown
这是正文^[脚注内容写在这里，自动编排序入文末]，继续正文。
```

- 内容在 `^[ ... ]` 之间，**到第一个 `]` 结束**——内容内不能再含未转义的 `]`。
- 不能跨段落；适合一两句话的短注释。
- 阅读视图点击或悬停可查看内容。

### 2.2 标准脚注

```markdown
这是正文[^1]，这也是[^note]。

[^1]: 编号脚注的内容。
[^note]: 命名脚注的内容，标识符可以是字母。
```

- 定义行 `[^id]: 内容` 可放在笔记**任意位置**（通常放文末），渲染时统一归入底部脚注区。
- 定义可含多段：后续段落缩进两个空格即属于同一脚注。
- 编号显示顺序按**引用出现顺序**排列，与定义顺序无关。

### 2.3 与闪卡高亮的配合铁律

- 行内脚注写在完型填空挖空内时，`]` 与闭合 `==` 之间**必须留一个空格**：
  - ✅ `==as;;床前明月光^[一作"看山月"] ==`
  - ❌ `==as;;床前明月光^[一作"看山月"]==`
- 闪卡技能用 `^[原文]` 行内脚注标注对原文的修复（见 `syntax-rules.md`），正是利用此语法。

### 2.4 常见错误

- ❌ 行内脚注内套 `]` → 提前闭合，后半截变成正文
- ❌ 定义行写成 `[^1]：`（中文冒号）→ 不被识别；必须用半角 `:`
- ❌ 表格单元格内大量使用脚注 → 布局易乱；表格内改用括号注释

## 3. 双链 `[[...]]`

```markdown
[[基本初等函数图像与数学公式]]           ← 链接整篇笔记
[[基本初等函数图像与数学公式|数学公式笔记]]  ← | 后自定义显示文本
[[基本初等函数图像与数学公式#3. 对数函数]]   ← # 链接到指定标题
[[笔记#^block-id]]                      ← 链接到带块 ID 的段落
```

- 只需写笔记名，Obsidian 在全库解析；重名笔记才需要补路径（如 `[[数学/函数]]`）。
- 链接指向不存在的笔记时显示为"未创建"状态，点击即新建——这是用链接做写作规划的特性。
- 在代码块/行内代码中的 `[[...]]` 不会被解析为链接。
- **改名/移动笔记必须用 `obsidian-cli move`**（见 `obsidian-cli.md`），全库双链自动更新；手动 `mv` 会产生大量断链。

## 4. 嵌入 `![[...]]`

在双链前加 `!`，把目标内容**内联显示**在当前笔记（transclusion）：

```markdown
![[另一篇笔记]]                  ← 整篇嵌入
![[另一篇笔记#某标题]]           ← 只嵌该标题小节
![[另一篇笔记#^block-id]]        ← 只嵌一个段落/列表项
![[图片.png]]                    ← 显示图片
![[图片.png|300]]                ← 限制宽度 300px
![[图片.png|300x200]]            ← 宽x高
![[文档.pdf]]                    ← 嵌入 PDF 阅读器
![[文档.pdf#page=3]]             ← 直接定位第 3 页
```

- 嵌入内容随源文件**实时联动**——改源笔记，所有嵌入处同步更新。
- 嵌入整篇笔记会连带其内部的图片与公式；循环嵌入（A 嵌 B、B 嵌 A）会被 Obsidian 截断，避免使用。
- 注意语法是 `![[...]]`（感叹号 + 双方括号），不要写成 `[[!...]]`。

## 5. 其他实用语法

| 语法 | 示例 | 说明 |
|------|------|------|
| 高亮 | `==重点==` | 黄底；Spaced Repetition 完型填空正是复用此语法（见 `syntax-rules.md`） |
| 注释 | `%% 草稿想法 %%` | 阅读视图完全隐藏；可跨行 |
| 标签 | `#闪卡/数学` | 支持多级 `/` 嵌套；闪卡调度依赖标签（见 SKILL.md 闪卡工作流） |
| 块 ID | 段落末尾 ` ^my-block` | 供 `[[#^my-block]]` 与 `![[#^my-block]]` 引用 |
| 删除线 | `~~废弃内容~~` | 标准语法 |
| 内部锚点 | 同篇内 `[[#标题]]` | 篇内跳转 |

## 6. 兼容性与常见误区

- **GitHub 兼容**：GitHub 的 alerts 仅支持 `NOTE`、`TIP`、`IMPORTANT`、`WARNING`、`CAUTION` 五种且要求大写。笔记若计划发布到 GitHub，Callout 只用这五种类型。
- `[[...]]`、`![[...]]`、`^[...]`、`%%`、`==` 均为 Obsidian 方言；离开 Obsidian（GitHub、普通 Markdown 编辑器）大多显示为原文本，撰写对外文档时慎用。
- Callout 与列表、表格混排时，后续内容必须保持 `>` 前缀，否则块提前结束。
- 行内脚注 `^[...]` 与标准脚注 `[^...]` 可以混用，编号会统一排序。
